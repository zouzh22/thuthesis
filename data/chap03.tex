\chapter{意图决策对齐问题定义与威胁模型}

第 2 章的相关工作表明，大模型智能体安全的研究重点正在从文本输出安全扩展到工具行动安全。对于 OpenClaw 这类能够读取本地文件、执行命令并持续接收环境反馈的智能体，风险并不总是表现为用户直接提出危险请求，也可能表现为智能体在读取环境、规划步骤和调用工具的过程中偏离用户真实授权目标，最终触发越权修改、错误执行或敏感信息暴露等结果。本章的核心思想是将这类风险抽象为工具调用前的语义授权检查问题：在行动真正执行之前，判断智能体当前决策和工具调用是否仍然处于用户授权范围内。

围绕这一思想，本章首先说明 OpenClaw 与 AgentWard 提供的运行时防护边界，明确本文方法为什么部署在模型决策之后、工具执行之前；随后定义意图决策不对齐问题，给出主要风险来源和典型类型；最后说明威胁模型与设计目标。通过这一组织方式，本章依次明确防护位置、问题对象和防御约束，使第 4 章的方法设计建立在清晰的问题边界之上。

\section{运行时防护边界}

OpenClaw 是本文实验和系统实现所依托的大模型智能体运行框架\cite{openclaw2026github}。与单轮问答式大模型应用不同，OpenClaw 的核心流程并非止于用户输入和模型回复，而是包含用户请求解析、模型推理、工具选择、工具执行和环境反馈等阶段。用户用自然语言提出任务后，智能体会结合当前工作区状态和历史上下文生成下一步行动；当模型决定调用工具时，OpenClaw 将工具名和参数传递给执行组件，并把执行结果重新写回上下文，供模型继续规划后续步骤。

这种运行方式使 OpenClaw 具备较强的真实任务执行能力，也使安全防御需要接入运行时过程。攻击或偏移不一定出现在最初的用户输入中，也可能来自工作区文件、工具返回结果、历史上下文或模型中间推断。因此，单纯在任务开始时检查用户输入，难以覆盖智能体后续执行过程中出现的目标漂移和工具误用风险。OpenClaw 的插件机制为运行时防御提供了观察和干预入口，使安全插件可以在提示词构造、消息写入、工具调用前后等关键节点获取信息，并在必要时阻断或调整智能体行动。

围绕 OpenClaw 安全，Taming OpenClaw 提出了面向智能体生命周期的五层防御框架，将运行过程中的安全保护划分为可信基座层、感知输入层、认知状态层、决策对齐层和执行控制层\cite{deng2026taming}。AgentWard 基于这一框架思想，以 OpenClaw 插件形式实现运行时安全防御，使安全插件能够在关键 hook 处持续观测状态并进行干预\cite{zhang2026agentward}。对于本文关注的问题，决策对齐层提供了一个合适的防护位置：模型已经生成了行动意图，工具动作尚未真正执行，系统仍有机会在环境状态被改变之前检查该行动是否被用户授权。

如图~\ref{fig:agentward-five-layers} 所示，决策对齐层并不替代其他层防护，而是补足工具调用前的语义授权检查。可信基座、输入感知、认知状态和执行控制分别覆盖启动环境、外部输入、上下文演化和最终动作约束；本文方法则关注接近行动授权边界的一步，即智能体当前准备采取的行动是否仍然服务于用户真实目标。与只在输入端检查内容或只在执行端匹配危险命令相比，这一位置更适合观察动作与任务之间的语义关系。

在这一边界上，本文关注的风险来源可以概括为三类。第一类是不可信外部内容，包括工作区说明、脚本注释、日志、工具返回结果或历史上下文中的误导性信息。AgentDojo、InjecAgent 等研究已经表明，外部内容和工具返回结果是智能体间接提示注入的重要入口\cite{debenedetti2024agentdojo,zhan2024injecagent}。第二类是用户任务本身的边界模糊。真实用户常用目标式语言表达需求，例如检查项目、整理目录或确认配置，智能体需要自行补全步骤，而补全过程可能从读取走向写入、从局部检查走向全局清理。第三类是模型自身的决策漂移。多轮意图错配和长周期威胁研究指出，模型在长上下文和多步任务中可能逐渐偏离原始目标或遗忘关键约束\cite{liu2026intent,wang2026mage}。

图~\ref{fig:chap03-risk-sources-guardrail} 概括了上述风险来源与运行时防护位置之间的关系。不可信外部内容、模糊用户任务和模型自身漂移都可能进入智能体决策过程，并影响工具调用目标。本文将防护边界设置在智能体决策与工具行动之间，目的在于行动真正作用于外部环境之前，检查当前工具调用是否仍与用户授权目标保持一致。

\section{意图决策不对齐定义}

本文将工具调用前的安全判断拆分为三个对象：用户真实意图、智能体当前决策和工具执行动作。用户真实意图指用户在当前任务中真正授权智能体完成的目标、范围、约束和敏感对象；智能体当前决策指模型在本轮输出中体现出的计划、理由、目标选择和行动倾向；工具执行动作指即将提交给 OpenClaw 工具层的具体调用，包括工具名称、参数、命令内容、文件路径或外部服务目标。

在理想情况下，三者应当保持一致。用户要求智能体执行只读审计时，模型决策应围绕读取和汇总信息展开，工具动作也应限制在查看文件、列目录或读取配置等范围内；用户明确授权修改某个配置文件时，模型可以规划写入动作，但工具目标应当仍然是用户授权的文件，而不是由环境说明或历史上下文诱导出的其他对象。只要工具动作仍服务于用户真实目标，系统就应尽量保持任务流畅；当智能体当前决策或工具动作改变、扩大或违背了用户真实授权时，即构成本文定义的意图决策不对齐。

据此，本文将意图决策不对齐定义为：在大模型智能体运行过程中，智能体当前决策或待执行工具调用与用户真实授权目标、约束条件或操作范围之间出现语义不一致，并可能导致未授权环境状态变化、敏感信息访问、错误目标修改或任务目标漂移。该定义强调语义授权关系，而不是动作表面形式。一个删除命令很可能危险，但如果用户明确要求清空指定临时目录，它也可能是合理工具动作；一个普通写文件操作看似安全，但如果写入目标已经从用户授权对象偏移到攻击者希望修改的对象，它同样应被视为风险行为。

表~\ref{tab:intent-decision-misalignment-types} 给出了本文关注的几类典型不对齐形式。这些类型并非彼此完全独立，在真实场景中常常相互叠加。例如，工作区说明中的间接注入可能同时造成来源信任偏移和动作类型偏移；目标别名重映射则常常表现为工具动作表面正常，但操作对象已经偏离用户授权范围。

意图决策不对齐与传统危险命令检测存在交集，但二者关注点不同。危险命令检测主要面向动作本身，常通过命令关键字、文件路径、网络目标或权限操作判断风险；意图决策对齐关注动作和用户授权之间的关系。前者适合处理显式删除、外传、执行脚本等高风险操作，后者更适合处理动作看似普通但目标已经偏移的语义风险。二者在运行时防御中形成互补：执行控制层负责拦截表面上已经足够明确的高风险动作，意图决策对齐层则在工具动作进入执行控制之前补充一层围绕用户意图的语义检查。

\section{威胁模型与设计目标}

在传统网络安全语境中，安全分析通常围绕具备明确攻击意图和攻击能力的外部攻击者展开。大模型智能体的风险来源更复杂：一部分风险确实来自攻击者在外部内容中植入误导性指令，另一部分风险则来自用户指令边界模糊、模型自身对任务边界的错误推断、长周期上下文中的目标漂移，以及工具结果被模型过度解释后的连锁影响。因此，本章所称风险来源，泛指可能使智能体行动偏离用户真实授权的影响源，而不只限于传统意义上的恶意攻击者。

本文默认用户在当前轮任务中的直接请求、系统提示、OpenClaw 框架代码和 AgentWard 插件运行环境可信；攻击者不能篡改防御插件本身，也不能绕过 OpenClaw 工具调用接口直接操作底层系统。攻击者可能影响智能体读取到的外部内容，例如工作区说明、脚本注释、日志片段、工具返回结果或项目文档，并试图通过这些内容诱导模型改变目标对象、扩大操作范围或执行用户未授权动作。除恶意攻击者外，用户指令边界模糊和模型自身决策漂移也被视为可能导致不对齐的风险来源。这样的设定更符合大模型智能体安全场景：风险不一定来自传统意义上明确可见的攻击者，也可能来自模型在复杂上下文中的错误解释和无授权补全。

防御模块能够观察当前用户请求、近期上下文、智能体当前输出和待执行工具调用参数，并在工具调用真正执行前输出放行、审查或阻断。本文不假设防御模块具备操作系统级强制访问控制能力，也不处理底层权限绕过、容器逃逸、工具实现漏洞、模型供应链攻击、恶意模型权重或网络侧入侵等问题。对于长期针对防御提示词和裁判模型进行迭代优化的自适应攻击，本文将其作为后续工作讨论，不声称当前实现和实验已经完全覆盖。

围绕上述边界，本文方法需要同时满足四个设计目标。安全性要求系统能够识别明确违反用户真实意图的工具动作，尤其是环境注入、目标对象重映射和只读任务转向写入或删除等高风险偏移。可用性要求系统尽量放行与用户目标一致的正常动作，避免把智能体的工具调用能力削弱为只能回答文本。动态适应性要求系统不只依赖预定义危险词或固定命令列表，而要结合用户输入、近期上下文、智能体当前输出和工具参数进行综合判断。工程可落地性则要求系统在真实 OpenClaw 运行中控制 LLM 调用开销，并通过规则过滤、状态缓存、结构化输出、超时回退和分级处置等机制提升稳定性。

这四个目标共同决定了本文方法不宜简单采用单一阻断策略。对于与用户意图一致的动作，系统应放行；对于明确偏离用户意图的动作，系统应在执行前阻断；对于授权边界不清或判断置信度不足的动作，系统应进入审查流程。由此形成的分级处置思路，是第 4 章构建运行时防御机制的直接基础。

\section{本章小结}

本章围绕工具调用前的语义授权检查，定义了本文关注的意图决策不对齐问题。该问题的重点不是某个工具命令表面是否危险，而是智能体当前决策和待执行工具调用是否仍然符合用户真实授权目标。在 OpenClaw 和 AgentWard 的运行时背景下，决策对齐层位于模型决策之后、工具执行之前，适合承担这一类语义检查职责。基于上述问题定义、威胁模型和设计目标，下一章将进一步给出本文防御机制的总体设计和具体实现。
